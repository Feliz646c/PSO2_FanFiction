## 3. 改善案：GitHubリポジトリの構成

```
PSO2_FanFiction/  (GitHub private repo)
├── CLAUDE.md              # 地図＋運用ルール。AGENTS.mdの内容を統合、①の実パスに合わせて書き直す
├── AGENTS.md              # Claude以外のAI向けに残すなら、CLAUDE.mdを参照する短い版にする
├── README.md              # 人間向けの案内（構成・更新の流れ）
├── .claude/
│   ├── agents/            # ②から移す（creative-* 3体）
│   ├── agent-memory/      # ②から移す。入れ子の誤作成分は統合
│   └── skills/            # 新設（下記4）
├── canon/  changelog/     # 現状どおり
├── sessions/
│   ├── 構想/              # 統合世界セッション構想（2版を統合後に1本化）
│   ├── 開催セッション/    # 各回フォルダ
│   ├── 参加セッション/    # ②から移す
│   └── logs/
├── characters/reports/
├── stories/
├── drafts/                # 現状どおり（正史ではない）
└── work/
```

Claude Codeの仕様では、プロジェクト用スキルは `.claude/skills/<名前>/SKILL.md`、サブエージェントは `.claude/agents/` に置き、どちらもリポジトリにコミットして共有する前提になっている。サブエージェントの `memory: project` は `.claude/agent-memory/<名前>/` に保存され、これもバージョン管理で共有できる。
- 出典：[Claude Code Docs: Skills](https://code.claude.com/docs/en/skills)、[Claude Code Docs: Subagents](https://code.claude.com/docs/en/sub-agents)

## 4. 改善案：作るとよいSkills（候補）

| スキル名（仮） | やること | 今の手作業 |
|---|---|---|
| `canon-update` | 確定した設定をcanon本体へ反映し、【更新履歴】追記・旧本文のchangelog移送・設定台帳更新までを一括で行う。ブランチを切ってPRを出す | CLAUDE.md「変更・撤回を行うときの手順」を毎回読ませている |
| `consistency-check` | 指定した変更について、00〜03との公理矛盾、05⇔08の整合、時系列・因果をチェックしてレポートを出す | drafts/consistency-review を都度作成 |
| `script-review` | 台本の精査。情景描写は事実列挙、PCの行動・思考を強制しない等のルールで確認 | プロジェクトメモリの「script-narration-style」で伝えている |
| `arks-report` | ARKS-Reportの構成案・下書きを、公開範囲の型に沿って作る | プロジェクトメモリ「arks-report」で伝えている |
| `session-log-import` | ログ原本txtを整形して保存し、「実際に何が起きたか」の要約と確定候補を抜き出す | work/ の logedit 設定を使って手作業 |

各スキルは「どの資料を読み、どの区分（確定／確定方向／有力案／未決）で書くか」を手順として持つ。**確定への昇格はユーザーの明示が必要**というルールは、全スキルに共通で書き込む。
