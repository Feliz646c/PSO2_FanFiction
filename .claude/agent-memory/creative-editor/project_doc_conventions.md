提案・改稿を出す際は、提案者が既に確立している以下の運用に合わせて出力する。

## 常時守る書式

- **設定状態タグを必ず付ける**：【確定設定】【確定方向】【有力案】【未決事項】。タグなしの提案は資料に取り込めない。
- **正本（single source of truth）を跨がない**：世界史＝00／人物＝01／用語＝02／残響物の実物＝03（定義は02）／統合世界セッション全体＝05／術式＝06／艦＝07／カジノ編＝08。同じ内容を二重掲載しない設計。提案時は「どのファイルのどの節へ入るか」まで指定する。
- **後発資料が旧案を明示的に更新している場合は後発を優先**（00 §0で宣言済み）。
- セッション限りの便宜的行動を人物の恒常設定へ一般化しない／参加者側の設定は資料側で確定しない（旧04由来の思想。08・05にも適用する）。
- 資料内の相互参照は**ファイル名のみ**で書く（パス表記はしない）。

- **`changelog/` ＝変遷史。** 撤回された設定の旧本文（原文のまま・要約しない）と、役割を終えた更新履歴エントリの保管先。**正本ではない。現行設定の典拠に使わない。**

- **エントリ見出しは本体の【更新履歴】と一字一句同じ**（`YYYY-MM-DD（n）── 見出し`）。日付＋連番が本体↔変遷史のリンクキー。新しいものが上。
- 書式のひな形は `changelog/00_世界設定マスター.md` の冒頭にある。エントリ項目は 種別／対象／現行の所在／経緯・理由／旧本文（原文保存）／現在も有効な制約。
- **変遷史は後から書き換えない。** 誤った判断も記録として原文で残し、「【この撤回は後に撤回された】」注記ブロックを足す形で訂正する（08のルクネリア姉妹設定が実例）。

### 移送時の最重要注意：禁止事項を変遷史へ送らない

撤回ブロックには**過去の記録**と**現在も生きているルール**が混在している。「今後この読みを前提に記述しないこと」「この語を使わない」は履歴ではない。

- 「かつてこう書かれていた／なぜ変わったか」 → **changelog/ へ**
- 「今後こう書くな」 → **本体に否定形の【確定設定】として残す**（例：「《デロイア》という部門は存在しない」）

**迷ったら本体に残す。** 変遷史へ送り損ねて失うのは検索性だけだが、生きている情報を送ると見落とされる。現在進行中の議論・ごく最近の変更・撤回自体が覆り得るものも本体に残してよい。

- GM専用・非公開区分は changelog/ へ移しても引き継ぐ（03へ書き出さない原則は変遷史にも適用）。

**Why:** 提案者は資料を「地図（CLAUDE.md）」と「実体（canon/・05）」に分け、変更履歴は各ファイル側に書く方針。そのうえで2026-09-17に「本体は確実に最新版だけ」という方針を追加決定した。書式を外した提案は取り込みコストが高く採用されにくい。

**How to apply:** 改善提案は「対象ファイル・対象節・設定状態タグ・置換する旧記述（あれば）」の4点セットで書く。**差し替え提案では、新本文とあわせて「changelog/ の対応ファイルへ送る旧本文」と「本体に残す禁止事項」を分けて示す。** 本体へ【撤回設定】ブロックを新設する提案はもうしない。
