**設定資料（00〜05）の【確定設定】【確定方向】は、実行台本より古いことがある。台本と食い違ったとき、自動的に資料側を正としない。**

**Why:** 2026-09-10、criticがカジノ台本の「04確定設定からの逸脱」を致命的10件として報告したところ、作者は**そのうち大半について「04の確定設定こそが誤り／古い」と判断し、04を台本へ寄せて書き換えるよう指示した。** 台本は作者が実際に走らせる直前に書いたものであり、**最新の意図が入っている。** 資料は前回更新時点で凍結されている。同じことは2026-09-10（1）の警備員バニーA／Bの特徴更新でも起きており、そのときも「台本を正とする」と明記されている。

作者が04側の記述を採らなかった理由には、繰り返し現れる判断基準がある。

- **PC側の動機として弱いものは却下される**（陽動依頼→「元の世界へ帰れるかもしれない」へ）。PCが自分の利益で動ける形にする。
- **PCのフラストレーションを溜めたまま終わらせない**（コルネオ戦で必ず一度勝たせる）。
- **不要な機構は置かない**（VIP資格のシステム自動判定→コルネオの気まぐれ）。判定装置より人物の裁量。
- **説明台詞で辻褄を合わせない**（「残響物は正しく機能していない」を削除）。

**How to apply:**
- 資料と台本の食い違いを見つけたら、**どちらが誤りかを断定せず、両方の可能性を提示して作者に判断を仰ぐ。** 「台本が資料に違反している」という一方向の書き方をしない。
- 資料側を書き換える指示が出たら、**旧記述は【撤回設定】として残し**、更新履歴に新旧対照表を書く（[[project-doc-conventions]]）。
- 資料を改訂したら、**その資料を参照している他の資料（01の人物の役割、05の位置付け）も同じ日付で追随させる。**
