**「ログに一度も出てこない」ことを根拠に、その設定が存在しない・採用されなかったと結論しないこと。卓上で未開示だっただけ、という可能性を必ず併記し、判断は提案者に仰ぐ。**

**Why:** 2026-09-14のログ照合で、Cパートの少女とルクネリアの姉妹設定について「ログに『妹』『姉』の語は皆無 → 採用されずに落ちた → 今後姉妹として扱わない」と断定した。**提案者はこれを誤りと判定し、姉妹設定を正式に復活させた。** 実際には設定は生きており、卓上で開示されなかっただけだった（後日談で二人の再会を描く予定）。**ログ上の観測（語が出現しない）は正しかったが、そこから「設定が存在しない」と推論した部分が誤っていた。** GMの頭の中にはあるが場に出さなかった情報は常に存在しうる。

**How to apply:**
- ログ照合では**「開示されたか」と「存在するか」を必ず二段に分ける。** 書くのは「卓上で開示されていない」まで。「存在しない」「落ちた」「今後扱わない」は書かない（[[feedback-canon-vs-script]]と同じく、断定せず作者判断を仰ぐ）。
- 開催前プロット（セッション情報.mdのプロット節）に記述がある設定は、**ログに出なくても生存を疑う側に倒す。** 姉妹設定は実際にプロット節に「ディーラーバニーの妹」として明記されていた。
- 逆に、**未開示であることから来る制約は生き続ける**：復活後もその場面の主題は変わらず、登場人物は関係を知らないまま行動している。復活＝場面の読み替えではない。
- 撤回が撤回された記述は、**原文を残したまま「この撤回は撤回された」マークを足す**（[[project-doc-conventions]]）。
