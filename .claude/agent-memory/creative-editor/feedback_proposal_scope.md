レビューを出したあと、提案者は**★優先だけでなく任意項目まで含めた全提案の改稿案作成**を指示してきた。ファイル分割（01→06切り出し）、見出し番号の全面振り直し、新規ファイル新設といった大規模な構造変更も含めて受け入れられている。

**Why:** 提案者は資料を長期運用する前提で整備しており、「今のうちに構造ごと直す」ことのコストを許容する。小さく刻んだ安全な提案よりも、影響範囲を明示した上での抜本案を評価する。

**How to apply:**
- レビュー時に「任意・優先度低」と付けた項目も遠慮せず出す。切るかどうかは提案者が決める。
- 改稿案を求められたら**方針説明ではなく、そのまま貼り付けられる実文**を書く。設定状態タグ、対象節、撤回する旧記述を必ず併記する。
- 機械的な繰り返し作業（番号振り直し、全項目へのヘッダ付与）は、最初の数件を実例として示し、残りは適用ルールを明文化する形でよい。
- 分量が大きい場合は**ファイル単位**でまとめる（00用／01用／…）。最後に適用順序（依存関係）を添える。
- ただし**方向性が未確定の論点を改稿案の形で勝手に確定させない**という制約は明示的に課された。未確定のものは「検討を要する論点メモ」に留める。この線引きは厳守する。

**【追記（2026-09-14）】【要確認】提案の裁定は、しばしば「承認＋さらに一段強い形」で返ってくる。**

**Why:** ユニエラの生命研究部門《アンテレイア》への再配置を【要確認】で出したところ、作者は確定を与えたうえで**「そも、ユニエラが部門自体を設立したと考えるのが自然では？」**と、こちらの案より踏み込んだ形を指定した。編集側が公理（統合以前の記憶を持たない）を恐れて所属止まりにしていた部分を、作者は**人物の自然な行動**として一段進めた。

**How to apply:**
- 公理に触れそうな要素は**丸ごと避けるのではなく、公理と両立する読み筋を添えて【要確認】に出す。** 判断は作者が下す。
- 作者が**「使う予定はない」と言った一致・符合**は、資料に**事実として一行書くだけ**にする。伏線化・含み・「本人は何かを感じていた」系の示唆を足さない。**書かないのではなく、意味づけしない。**
- 格上げ時は【要確認】を消して確定へ書き換え、**参照側（00・05・08）に残った「再検討中」表記も同時に潰す。** 未決のまま残すべき隣接項目（職名・役職、他の人物の認識、共同体の有無）は明示的に「これは解消しない」と書き添える。
