**セッションで起きたことを資料化する際、「GM側が提示した事象」と「参加者が持ち込んだもの」を分けて扱う。後者を一般則へ格上げしない。**

**Why:** 2026-09-11カジノ編では、クライマックスの解決（コルネオの残響物の無力化）が**GMの用意した正解ではなく、参加者がその場で組み立てたもの**だった。GMが行ったのは「異常を一定のリズムで提示し続けること」と「筋の通った工夫を必ず通すこと」の二つだけ。**これを『攻略手順』として資料に書き起こすと、次に同じ構造を出したとき「用意された謎解き」に変質してしまう。**
同様に、参加者の能力で成立した処理（首輪の遠隔爆破システムの一斉解除など）を「首輪はハッキングで解除できる」という仕様にすると、世界の側の設定が特定PCの都合で固定されてしまう。

**How to apply:**

- 資料へ書くのは**「何が起きたか」**であって**「どうすれば解けるか」**ではない。
- 参加者の一回限りの処理は「一度そうしたという事実だけを残す」と明記する（08 §16の既存運用に合わせる）。
- **PCの推測をGMの正解として採用しない。** 卓で疑問が提示されGMが答えなかった箇所は、**答えなかったという事実ごと残す**（例：幸運が戻っていたコルネオをフィクスが素通りで殺した件）。
- 逆に、**GMがその場で即興で返した処理は積極的に拾う。** 参加者が自発的に作った役割（「敗北者」「用心棒」）を卓へ反映した例など、進行の知見として価値が高い。
- 一般則にしてよいのは、**GM側が繰り返し提示したもの**（賽の音のリズム、ディーラー4人の性格づけ、敗者救済の存在）だけ。

## 【2026-09-14（3）作者回答による重要な補正】

**1. GMがアドリブで情報を開示したことを「問題」「制約」として書かない。**
作者の言：「参加者に情報を提示する事自体は悪い事ではないので、アドリブで開示しました。」
カジノ編でフィクスが「実験」「クライアント」の二語を漏らした件について、当初こちらは【開示範囲の事故】という論調で書いていたが、**作者はこれを意図的な裁量開示だと明言した。**
→ **アドリブ開示を見つけたら、まず「なぜこれを開示したのか」という設計上の効果を探す。** 減点として報告しない。ただし**「既に切ったカードだから同じ情報で驚かせ直せない」という運用上の帰結は残す。**

**2. 「機構の説明」と「攻略手順」は別物である。**
「参加者が組み立てた解法を正解として書き起こさない」というルールは、**世界の側の理屈（なぜそれが効くのか）を書くことまで禁じてはいない。**
→ **書いてよい：** 機構、解法の**カテゴリ**、判定のための物差し。
→ **書かない：** 順序立てられた手順書（「こう動けば解ける」）。
カジノ編では、残響物の機構と想定解3種を §14 に書きつつ、§4F・§16 の「参加者が現場で組み立てた」という注記をそのまま有効なものとして併存させた。**この併存の形を今後も踏襲する。**
