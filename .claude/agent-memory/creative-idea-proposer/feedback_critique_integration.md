このプロジェクトでは「提案者が複数案を出す → 批評者が整合性を検証する → 提案者が指摘を潰した**一本の統合案**を出す」という往復運用が行われる。批評フェーズ後は複数案の並列提示ではなく、**指摘番号に対して逐一どう解決したかを対応づけた単一案**が求められる。

**Why:** 作者は設定を長期運用しており、「面白いが整合しない案」を資料へ入れることを避けたい。一方で提案の面白さは落としたくないため、批評を潰す作業を提案者側にやらせる設計になっている。

**How to apply:**
- 批評後の統合案では、①〜⑪のような指摘番号への対応表を必ず添える。どの指摘をどの機構で解消したかを1行で言い切る。
- 統合しても未確定にせざるを得ない部分（用語名、後日談の扱い等）は、**そこだけ複数の選択肢**として残す。確定させない制約は批評後も生きている。
- 既存の確定設定を「書き換えずに読み替える」解決を優先する。批評者は00〜03との衝突に最も厳しい。
- 過去に否定された発想を再提出しない。特に「容器へ移して器を破壊すれば完結する」は黒き邪竜編・ルーサー編の前例と古代の凝縮によって三重に否定されている。
