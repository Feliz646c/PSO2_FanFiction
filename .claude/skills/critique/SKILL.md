# 批評

対象の**弱点**を、根拠つきで深刻度順に挙げる。目的は、ユーザーが判断する材料を出すこと。
**このスキルでは資料も本文も書き換えない。** 直すかどうか、どう直すかはユーザーが決める。

## 姿勢
- 迎合しない。良い点を並べて終わらせない。指摘が見つからない場合は「見つからなかった」と書き、何を確認したかを書く。
- 指摘は「好み」ではなく「なぜ弱いか」で書く。根拠（canonの節、ログ、本文の該当箇所、主題）を付ける。
- 批評は提案であり、設定を確定・変更するものではない。【確定設定】そのものを批判する場合も、変更はユーザーの判断に委ねる。
- 小説本文の文体については、**既存の小説（`stories/`）が正**。筆者の癖（語彙、リズム、句読点の打ち方など）は直す対象にしない。誤字脱字・意味の通らない箇所・設定との矛盾と、癖とを区別する。

## 観点
対象に合うものだけ使う。
1. **因果と動機**：その人物がそう動く理由は、既存の設定と状況から説明できるか。都合で動いていないか。
2. **主題**：作品や章の主題（例：05 §21 のテーマ上の到達点）と噛み合っているか。主題を説明台詞で済ませていないか。
3. **人物の一貫性**：思想・口調・能力の制限（canon/01・06）とずれていないか。
4. **既視感・予定調和**：展開が読めすぎないか。ありがちな型に頼っていないか。
5. **体験**：セッションなら参加者（PL）が選び、推理し、動ける余地があるか。小説なら読者に伝わる順番になっているか。
6. **説明過多・抽象化**：理屈を積み上げすぎていないか。抽象的な言葉で中身をぼかしていないか。
7. **既存設定との緊張**：矛盾まではいかないが、将来の展開を縛る・別の設定と食い合う箇所。明確な矛盾は `consistency-check` で扱う。

## 出力形式
```
### 批評
総評：（1〜2文）

1. 【深刻度：高／中／低】指摘の見出し
   - 該当：（ファイル・節・本文の該当箇所）
   - 問題：（なぜ弱いか）
   - 根拠：（canon・ログ・主題など）
   - 方向性：（直すならどの方向か。案であり確定ではない）

（最大5件。深刻度の高い順）

残すべき点：（1〜2件。直すときに壊してはいけない部分）
確認した範囲：（読んだ資料）
```
