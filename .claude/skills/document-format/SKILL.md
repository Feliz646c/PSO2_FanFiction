# 資料提示の書式（2026-10-30 ユーザー指示）

ユーザーへ資料を出すときは、下のひな形で書き、仕上げに `yomiyasu` スキルで文章を整える。
見本は `drafts/次回セッション/ブレスト_11_台本の骨子と未決点.md`。

小説・台本の本文には適用しない。文体の正本は `stories/` の既存小説と CLAUDE.md「執筆の文体」節、台本の描写は `script-review` スキルに従う。

## ひな形

```markdown
# <題材> <資料名>：<この資料で扱うこと>（YYYY-MM-DD）

この資料は提案であり、canonではない。<何のために、何を材料に整理したか>を2〜3文で書く。

## 1. <現状・前提>
決まっていることを書く。場面や項目を並べるときだけ表を使い、各行に典拠（ファイル名・節）を付ける。

## 2. <決定済みの前提>
地の文の段落で書く。話題ごとに段落を分ける。

## 3. <未決点・論点>
ユーザーに決めてほしいことを、先に決めたいものから並べる。
表の列は「# ／論点／現状／推し」。推しはClaudeの提案であることを明記する。
後回しにできるものは地の文でまとめる。

## 4. 批評
`critique` スキルの観点で、弱点を深刻度順に最大5件。
各件は見出し1行＋地の文の段落（該当・問題・根拠・方向性を文章でつなぐ）。
最後に「残すべき点」と「確認した範囲」を地の文で書く。

## 5. 進め方の案
次に何をするかを段落1つで書く。
```

## yomiyasuで整えるときの注意

- 一文に一つの事実を書き、「誰が・何を・どうする」が文だけで分かるようにする。
- 箇条書きは表と批評の見出しに限り、ほかは地の文にする。太字は使わない（canonのラベル【確定設定】などは残す）。
- 矢印（→）、文末コロン、英単語前後の半角空白を使わない。「――」は原文の台詞・名乗りの引用に限る。
- 仕上げにリンター（`yomiyasu` スキルの `scripts/yomiyasu_lint.py`）をかける。「正本」「装置」「残響」など、本作の用語として正当な語は言い換えない。
- 典拠（ファイル名・節番号）、日付、提案者の決定内容は削らない。区分（確定・有力案・未決）を言い換えで変えない。
